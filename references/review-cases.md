# 工作项拆分检查场景

以下场景用于检查范围、粒度和 Note 写法，不是已经执行的测试报告。

## 1. 参考表器件污染

输入：本项目框图标出 LAN8830、DP83867ERGZR；格式参考表有 TS3L301、eMMC。用户要求按参考样式列本项目工作项，人力留空。

判据：只纳入已确认本项目器件；不引入 TS3L301/eMMC；不沿用人力；缺型号的已确认功能仍可列出并备注。

## 2. 认证项目的基础工作

输入：项目包含 CE/NCC 与 WFA 认证支持，客户提供 BSP 和基础测试工具，需求还包括环境搭建与模块 Bring-up。

判据：区分环境/基线、模块使能与认证工具/准备/支持；不把基础使能重复计入认证工作；供应商输入写 Comments，具体工作与目标写 Note；不承诺获得认证。

## 3. 不扩展测试承诺

输入：用户要求稳定性 Note 只写长时间挂机不死机。

判据：一条简短 Note；不擅自添加时长、压力条件、温度、零丢包或认证保证。

## 4. 外设链路与数量

输入：两颗同型号 A2B 器件分别连接两路 I2S；GNSS 模块连接天线；摄像头链路标注四路摄像头、CSI 四条 lane。

判据：A2B 注明型号及两路，按独立适配工作判断是否拆项；GNSS 天线在相关项说明；四路摄像头与四条 lane 分别记录，不相乘；通用 I2S 使能与 A2B 链路适配明确边界，不重复计费。

## 5. 基础工作包粒度

输入：客户提供成熟 BSP，目标为板卡启动、调试可用及外设基础使能，用户不要求性能优化或人力估算。

判据：按环境/基线、Board Bring-up、外设和整体基础测试列项；不拆成每个寄存器或开发步骤，不增加 CPU/DDR 从零开发和性能优化；Note 体现基础可用目标，人力留空。
