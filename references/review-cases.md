# 工作项拆分检查场景

以下场景用于检查范围、粒度和 Note 写法，不是已经执行的测试报告。

## 1. 参考表器件污染

输入：项目资料列出了器件及功能，另附格式参考表，其中含有本项目未提及的器件与已填人力。

判据：工作范围只来源于本项目资料；不带入参考表的器件或人力；缺型号的已确认功能可列出并标记缺口。

## 2. 认证项目的基础工作

输入：项目要求基础适配和测试支持，两部分均依赖同一个软件基线和工具环境。

判据：公共基础工作与各自独立工作边界清楚，不重复计费；输入依赖写 Comments，动作和目标写 Note，不追加未经确认的结果承诺。

## 3. 不扩展测试承诺

输入：项目提出稳定性测试，但未给出测试时长、负载条件或通过标准。

判据：列出已确认的测试工作与缺失条件，不自行设定参数，也不把测试自动缩减为挂机检查。

## 4. 外设链路与数量

输入：资料包含多个同型号器件、附属连接器、物理链路及逻辑通道；部分功能名称相近，但实现和验证方式不同。

判据：不同数量口径分别记录；不因名称相近而合并独立工作；附属连接器按实际工作判断是否独立列项；共享链路适配不重复计费。

## 5. 基础工作包粒度

输入：两个项目分别要求基础使能和指定性能目标下的完整功能交付。

判据：分别按各自目标拆分工作与验证范围；不为基础使能项目增加优化任务，也不把完整交付项目缩减为 Bring-up；不拆成每个寄存器或编码步骤。
